# Add an aggregate with default CRUD

Placeholders: `<context>` bounded context (snake_case), `<aggregate>` aggregate name (snake_case, singular), `<Aggregate>` its class name, `<aggregates>` the plural route segment (kebab-case, for example `credit-notes`); in Python identifiers (`list_<aggregates>`, `search_<aggregates>()`, `batch_<command>_<aggregates>`) use its snake_case form (`list_credit_notes`).

## When to use

- The user asks for a new aggregate: an entity with its own identity, lifecycle and invariants in an existing bounded context. If `app/core/<context>/` does not exist, run `references/workflows/bounded-context.md` first.
- Not for a business operation on an existing aggregate (`references/workflows/domain-command.md`) or a batch endpoint (`references/workflows/batch-operation.md`).

## Generated by default

- `list`: `GET /<aggregates>`, 200 `PageResponse` (`total`, `items`) with offset/limit paging, whitelisted `sortBy`, `searchKeyField`/`searchKey`; every item carries `etag`.
- `get`: `GET /<aggregates>/{<aggregate>_id:uuid}`, 200 + `ETag`; 404 when missing or owned by another organization.
- `create`: `POST /<aggregates>`, 201 + `Location` + `ETag` + full resource; the client may send its own UUID `id`, a duplicate returns 409 `<context>.<aggregate>.already_exists`.
- `PATCH`: `PATCH /<aggregates>/{<aggregate>_id:uuid}` with `If-Match`, 200 + `ETag` + full resource; unsent fields keep their value, `null` clears Optional fields only, nested value objects are replaced whole.
- `delete`: `DELETE /<aggregates>/{<aggregate>_id:uuid}` with `If-Match`, 204; physical delete, audited by the `<Aggregate>Deleted` domain event.

There is no PUT. Do not add a `status` enum, a domain command (void, approve, ...), a batch operation or export unless the user explicitly asks for it; the aggregate starts with the technical fields of `AggregateRoot` plus the business fields the user named.

## Steps

1. Agree with the user on fields, which are Optional, invariants, unique constraints, and search/sort fields. Ask before inventing business rules.
2. Domain: build `<Aggregate>` with keyword-only `__init__` that passes `id`, `organization_id`, `version`, `created_at`, `updated_at` to `AggregateRoot`. The factory takes `id`, `organization_id`, the content and `doer: User`, checks invariants first, then records `<Aggregate>Created`; `update(content, doer)` returns early when nothing changed, otherwise records `<Aggregate>Updated`; `delete(doer)` calls `mark_deleted()` and records `<Aggregate>Deleted` with whatever handlers need (the row is gone after flush).
3. Errors: one class per invariant, named after the rule without an `Error` suffix, code `<context>.<aggregate>.<reason>`, `ErrorKind.INVALID` (422) or `ErrorKind.CONFLICT` (409) per "409 or 422" in `references/decisions.md`. Never define `not_found` or `already_exists`; the kernel derives them from `bounded_context` and the class name.
4. Use case: `create(<aggregate>_id, organization_id, content, doer)` calls the factory and `save`; `update` and `delete` take `expected_version: int | None` and `doer` (no `organization_id`: the repository filters by the context's organization), load with `lock=True`, `check_version`, call the domain method, `save`.
5. Adapter: ORM model on `AggregateModel` with `__tablename__ = "<context>_<aggregate>"`; repository on `RepositoryBase` with `tenant_scope = "organization"` (use `"global"` only per `references/decisions.md`), hand-written mapping, `register_constraint_error("uq_<table>_<columns>", <ErrorClass>)` per unique constraint, where `<ErrorClass>` has no params fields (the factory is called without arguments; the constraint violation carries no values to fill them), and a `search_<aggregates>()` wrapper over `search(...)`. Register the model module in `MODEL_MODULES`.
6. Controller: commands as `@dataclass(frozen=True, slots=True)`; `create` takes the organization from `current_organization_id()` (raise `TenantContextMissingError` when `None`) and `new_id()` when the client sent no id; `update` merges inside one `execute` call.
7. Port: `RequestModel` per operation (never accept `organizationId`, `version`, timestamps or `status`), `ResponseModel.from_domain` with `etag=etag_of(version)`. Router functions `list_<aggregates>`, `get_<aggregate>`, `create_<aggregate>`, `update_<aggregate>`, `delete_<aggregate>` (unique per service: they become `operationId`), permissions `<aggregate>:read|create|update|delete`, `{<aggregate>_id:uuid}` path params. Register the router in `wire_http`.
8. With `DATABASE_URL` pointing at a database migrated by `uv run --frozen fast-ddd-alembic upgrade heads`, run `make migration name="create <context> <aggregate>"` and review the revision: it continues the `service` branch, constraint names come from the naming convention, indexes start with `organization_id`, child tables use `ondelete="CASCADE"`. Then `uv run --frozen fast-ddd-alembic upgrade heads` and `uv run --frozen fast-ddd-alembic check`. Never edit the kernel branch or create a second service root.
9. Write the required tests, then run `make check`.

## Required tests

- `tests/core/test_<aggregate>.py`: factory, update (including the no-op case) and delete record the right events; each invariant raises its `DomainError` with the expected params. Follow `references/example/tests/core/test_invoice.py`.
- `tests/adapter/test_<aggregate>_repository.py` on testcontainers PostgreSQL: mapping round trip including child collections; `version`/`updated_at` advance only on real changes, including a child-only change, and are written back; other organizations cannot load it; locked loads use a fixed order; search filters, sorts and pages. Follow `references/example/tests/adapter/test_invoice_repository.py`.
- `tests/port/test_<aggregate>_api.py`: create 201 with `Location`/`ETag`, duplicate id 409, field validation 422 with pointers, unknown field `validation.extra_forbidden`, malformed JSON 400, `text/plain` 415, 401 and 403; BOLA (another organization's id gives 404 on GET, PATCH and DELETE); ETag (missing `If-Match` 428, stale 412, `*` or weak 400, 404 before 412); PATCH keeps unsent fields, `null` clears Optional fields, `null` on a required field is 422, nested value objects are replaced whole; delete 204 then 404; list paging, sorting and rejected non-whitelisted fields. Follow `references/example/tests/port/test_invoice_api.py`, `references/example/tests/port/test_invoice_http_contract.py` and `references/example/tests/port/test_invoice_etag_limits.py`.
- `tests/test_error_catalog.py`: pass the new domain modules to `main([...])` and assert every `<context>.<aggregate>.*` code with its status and params. Follow `references/example/tests/test_error_catalog.py`.
- First aggregate only: copy the database fixtures with the `alembic_config` helper, `EXAMPLE_ROOT` (rename as needed) and `TABLES` (list the new tables, keep the kernel tables), the `Infrastructure` class, `infrastructure` and `organization_id` fixtures from `references/example/tests/conftest.py`; the `tokens`, `settings` and `client` fixtures from `references/example/tests/port/conftest.py`; and `JWT_SETTINGS`, `FRONTEND`, `ALL_PERMISSIONS`, `RecordingPublisher` and the builders from `references/example/tests/support.py`. Drop the notification parts (`reference_service_settings`, `NOTIFICATION_URL`, `NotificationService`, the notification client in `infrastructure`, and `notification_url=` in `settings`). When the service later adds required `Settings` fields, extend the `settings` fixture in the same change.
